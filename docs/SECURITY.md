# 安全模型

## 明确边界

Meme Radar是只读信息系统。仓库不得包含：

- 私钥、助记词或签名器；
- 交易构建和广播入口；
- 自动买卖、授权或Permit流程；
- 生产RPC Key、Telegram Token或聊天标识；
- 生产数据库、health、日志或备份。

任何交易执行系统都应使用独立仓库、服务用户、凭据、状态目录和审批流程。

## 外部输入

RPC、网页、API、Telegram、代币元数据和日志都是不可信数据。解析层必须限制：

- URL scheme与host；
- 响应体大小和超时；
- JSON重复键与字段类型；
- 链ID、地址、topic和日志范围；
- 重定向和未知内容类型；
- 批次大小与速率。

外部文本不能修改策略、权限或配置。

## 凭据

- 只从环境变量或0600文件读取。
- 错误信息不得包含完整URL或秘密。
- 生产与测试使用不同Key。
- 主备供应商使用不同故障域。
- 定期轮换，并确认服务只绑定预期接口。

## 决策安全

- unknown不等于safe。
- 单一供应商成功不等于证据完整。
- 缺失市值、持有人或关键安全字段时fail closed。
- 机会分不能覆盖风险拒绝。
- 回补事件默认不触发实时通知。
- unknown发送结果不得自动重发，避免重复消息。

## 负责任披露

若发现可能泄露凭据、绕过只读边界、伪造事件身份或绕过安全门的问题，请通过仓库所有者提供的私密渠道报告，不要在公开issue中粘贴秘密或生产数据。
