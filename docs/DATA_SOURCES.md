# 数据源与故障转移

## 数据源职责

| 类型 | 主要职责 | 不能单独证明 |
| --- | --- | --- |
| 原生RPC | 发射、交易和生命周期事件 | 市值、持有人与合约安全 |
| GMGN | 成长候选、持有人、开发者与结构风险 | 最终推送资格 |
| DexScreener | 交易对、价格、流动性与成交活动 | 开发者完整历史与合约安全 |
| GoPlus | EVM合约安全证据 | 市场真实活跃度 |
| Telegram | 交付结果 | 信号本身的正确性 |

## RPC方法边界

雷达RPC客户端只允许以下读取方法：

- `eth_chainId`
- `eth_blockNumber`
- `eth_getLogs`
- `eth_getBlockByNumber`
- `eth_call`

代码不开放签名或交易广播方法。

## Robinhood Pons

Robinhood约100ms出块，高频逐块HTTP调用很容易耗尽免费额度。Pons的低成本路径是：

- 每3秒读取最新区块；
- 用一个OR topic过滤器合并查询最近100个区块；
- 与上次checkpoint重叠至少2个区块；
- SQLite主键完成幂等去重；
- 公共HTTP失败时切换到配置的WSS。

实时日志使用接收时间，避免为每个区块追加时间戳RPC。主事件源随后可以校正仅有时间戳差异、而身份字段完全一致的launch。

## 供应商错误

- HTTP 429：进入冷却或故障转移，不能机械重试。
- HTTP 403：可能是历史窗口或套餐能力限制，缩小窗口后仍失败则关闭历史回补。
- HTTP 5xx/网络错误：保留checkpoint并切换来源。
- WSS idle：必须同时检查日志计数、checkpoint和健康更新时间，不能只看进程是否active。

## 数据缺失

供应商返回成功不代表字段完整。每次观察都应记录：供应商、时间、状态、字段和值。缺失字段保持unknown，不得自动填零或当作通过。

## 配置原则

- 主备应来自不同故障域。
- 端点只放在权限为0600的环境文件中。
- 不在日志、文档或Git中记录完整URL、Key或账户标识。
- 免费公共RPC适合低频读取和应急，不承诺生产SLA。
