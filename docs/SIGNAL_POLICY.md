# 信号与风控策略

## 候选优先级

优先级只分配补全预算，不决定能否推送。主要信号包括：

- 来源新鲜度；
- 元数据和创建者字段是否齐全；
- 叙事聚集和跨链同名聚集；
- 链公平权重；
- 同一创建者短时间连续发币惩罚。

高优先候选先查规模与市场，低优先候选延迟或放弃昂贵调用。

## 分阶段补全

1. 发现与标准化：链、合约、发射台、创建者、时间和事件身份。
2. 规模预检：市值、持有人数；不满足时不继续消耗安全API。
3. 市场确认：交易对、流动性、成交量、买卖笔数和独立买家。
4. 开发者证据：初始买入、卖出、持仓保留、团队持仓与历史行为。
5. 身份与叙事：同名合约、同名最高市值、跨链聚集。
6. 安全补全：合约、蜜罐、权限、集中度、bundler、insider等。
7. 最终评分与outbox。

候选可在约5、10、20、30分钟重新检查规模数据；任务状态保存在SQLite中。

## 统一硬门

当前代码中的规模边界是严格“大于”：

- 市值必须大于100,000美元；等于也拦截。
- 持有人数必须大于100；等于也拦截。
- 任一字段缺失时fail closed。

GMGN成长候选还要求最低流动性、5分钟成交量、买入/卖出活动和聪明钱数量。BSC/Base要求合约与所有者状态明确安全；Solana要求mint和freeze权限已放弃。

买卖比例采用组合门：当GMGN或DEX任一来源的买卖比达到1.0时，不因另一个来源低于1.0而单独拦截。成交量、买入数、卖出数和安全硬门仍独立生效。

## 开发者规则

系统关注的是开发者是否存在可验证的卖出行为。若开发者开盘买入后一直没有卖出，并且初始仓位仍近乎完整保留，则候选被拦截，以降低集中砸盘风险。缺少开发者证据不会视为安全。

## 同名合约

存在多个同名候选时，只允许已验证的最高市值合约继续；无法完整比较市值时fail closed。官方合约身份可使用明确的地址白名单，但不能靠名称或symbol自动推断。

## 评分

置信度衡量证据完整性，例如来源数量、元数据、创建时间、安全状态、卖出模拟、市场时间、买卖双方与创建者风险。

机会分衡量相对热度，例如叙事权重、叙事爆发、跨链聚集、独立买家、买卖结构、流动性和成交量。

评分只在硬门之后生效；高机会分不能覆盖安全拒绝。

## 通知语义

- `strong`：通过风险门且证据、机会达到强信号阈值。
- `medium` / `weak`：默认不进入正式推送。
- `suppress`：明确拒绝。
- 观察样本：若启用，必须单独标记、限量且不得描述为交易建议。
